# GWS-emoji-2-task-sheet

絵文字起点でタスク情報を共有シートへ同期する Google Workspace 自動化です。  
Google Workspace automation that syncs emoji-triggered task data into shared sheets.

## 概要

この README は、このリポジトリの役割を示すための最小 README です。
詳細な使い方、設計、運用ルールが必要な場合は今後追加します。

## 実装の範囲と用語

現在の [sample.gs](sample.gs) が行うのは、個人用シートから共有用シートへの**一方向の行追加**です。絵文字イベントを直接受信するコードは含まれていません。絵文字起点のワークフローで得た行を同期する後段として位置づけられます。

「転記元」は個人用シート、「転記先」は共有用シート、「済」は再転記を避ける管理値です。現在のサンプル設定では、2行目以降のA〜H列にデータがあり、I列が「済」ではない行を対象にします。たとえば架空のタスク名だけが入力された行も同期されるため、全項目が埋まるのを待つ処理ではありません。

## 背景と仕組み

[設計仕様書 v2.0](design-spec.md)は、個人の作業領域と共有領域を分け、二重入力や手動の転記操作を減らすことを目的にしています。転記元に紐づく Google Apps Script の `syncDataPeriodic()` を時間トリガーで実行し、`setValues` でまとめて追記した後に元シートへ「済」を記入する構成です。設計書の版は確認できますが、初版の成立日や実運用の開始日は記録からは確定できません。

## 導入と展開上の注意

サンプルの転記先ID、両シート名、列数、管理列、開始行を環境に合わせ、少数のテスト行で確認してから時間トリガーを設定します。共有先に出してよい列だけを選び、実行者が転記先の編集権限を持つことを確認してください。

後から元の行を修正しても共有先へ上書きする機能はなく、削除の同期も行いません。「済」を消すと追加行として再送されるので、重複に注意が必要です。また共有先への追記と「済」の更新は別処理であり、その間の失敗や並行実行に対する完全な重複防止を保証するものではありません。タスク台帳以外へ応用する際も、この追加型同期の範囲で列構成を合わせて利用します。
